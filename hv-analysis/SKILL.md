# 横纵分析法深度研究

横纵分析法由数字生命卡兹克（Khazix）提出，融合了语言学的历时与共时分析（索绪尔）、社会科学的纵向与横截面研究设计、商学院的案例研究法和竞争战略分析。它适用于产品、公司、概念和人物。

一份报告有三样东西：

- **纵轴**：沿时间把研究对象从诞生讲到今天。要写出因果，为什么在那个时间点做了那个选择，哪些早期决定把后来的路锁死了。
- **横轴**：在今天这个时间切面上，把它和竞品或同类放在一起比。
- **交汇**：把两条线叠起来，回答「它今天的位置是怎么被历史塑造的」「接下来会怎样」。

读者最后要的是交汇处的判断。只有年表和参数对照表，没有交汇，这份报告就没有完成。

## 开始之前

用户说的格式、篇幅和重点，优先于本文的任何默认值。他要 1500 字就写 1500 字，他要 HTML 就出 HTML。篇幅短，压的是写出来的字数，不是取证的范围：短报告照样把三条线查全，再挑最能改变判断的事实写进去。

研究对象已经明确（比如「用横纵分析法研究一下 Cursor」）就直接开始，不追问。对象有歧义、同名的东西不止一个时，问一句再动手。用户提到了研究动机或特别关心的方向，就把篇幅向那里倾斜。

这个 Skill 自带 `scripts/md_to_pdf.py` 和 `references/`。有的第三方市场只分发了 SKILL.md；要出 PDF 或 HTML 而脚本不在时，从官方仓库装完整目录，或者告诉用户只能先交 Markdown。不能说 PDF 已经生成而实际没有。

## 一、取证

报告的质量由取证决定。信息不够，后面写得再好也是空的。

**必须联网，而且当下的事只认当下的来源。** 你记忆里的版本号、价格、融资额、市场份额和「最新进展」多半已经过期。先确认今天的日期，再去查研究对象现在的状态。旧资料用来讲历史，现状只用当前有效的来源。用宿主实际提供的搜索和网页读取工具，不依赖某个固定的工具名。搜索用不了时先试已知的官方页面；仍然取不到证据，就交付已有的证据并写明缺口，不拿记忆冒充查到的结果。

**分三条线查，能并行就并行：**

- 纵向：起源、创始人或发起者的背景、发展历程、关键事件、版本迭代、融资、战略转向、危机和争议。
- 横向：有哪些竞品或同类，各自的特点、定价、体量，行业里的对比评测。
- 用户的真实声音：GitHub Issues、Reddit、X、知乎、Hacker News 等社区里的口碑、吐槽和实际用法。

宿主支持子 Agent 时把这三条线分出去并行查，交代给它们的是要弄清什么，不规定用什么手段；不支持就按顺序自己查。每条线都要换关键词多搜几轮，搜一次没结果不算查过。

**优先一手来源。** 几家媒体互相转载同一个错误，看起来像多方印证，其实只有一个来源。

| 信息类型 | 一手来源 |
|---|---|
| 产品更新、技术决策 | 官方博客、GitHub Release Notes、创始人本人的发言 |
| 融资、商业数据 | 公司公告、SEC 或工商文件 |
| 用户口碑 | GitHub Issues、Reddit、X、知乎上的原帖 |
| 行业分析 | 权威媒体的原创报道，不是转载 |
| 学术、技术原理 | arXiv 论文（`export.arxiv.org/api/query`）、Google Scholar、会议论文集 |

**边查边记台账。** 每个关键事实记四样：来源 URL，事情发生的时间，页面发布或更新的时间，来源的性质（一手、二手转述，还是当事方自己的说法）。发生时间和发布时间不是一回事，不能混。当事方自己报的数字（用户数、安装量、增长率）要写明是谁报的，有第三方数据就对照着写。证据的强弱在正文里如实标出来：

- 只有一个二手来源的，标「单一来源」；
- 各方说法冲突的，标「有分歧」，把两边各自怎么说、谁说的都写出来；
- 查不到的，写「该信息暂缺」，不补造；
- 你自己的预测和推断，明说是推断。

**查够了再写。** 动笔前问自己：

- 纵向能不能讲成一个完整的故事？有没有哪几年是空白？每个关键节点的前后各发生了什么：官方宣布之前谁已经先做了，宣布之后谁跟了、谁没跟？
- 最近三个月的动向查了吗？现状最容易漏的就是最新的那几件事。
- 横向的竞品列全了吗，有没有漏掉主要玩家？每一家是不是都查到了三样：它现在的处境，用户选它的真实理由，至少一条能指到原帖的用户声音。
- 有没有和你正在形成的判断相反的证据？专门搜一轮反面的。
- 关键的事实有没有可靠来源？有没有只凭一个来源就下的判断？表格里的每一格，是查过确实没有，还是没去查？

复杂的对象可以对照 [references/schema.json](references/schema.json) 逐项查缺（关键节点时间线、阶段划分、路径依赖、竞品列表等）。它是一张查漏的清单，不是报告的格式。不够就再搜，不凑合。

## 二、纵轴：从诞生到今天

这是报告的主体，篇幅最重。要写到这些：

- **起源**：它诞生在什么背景下，基于什么技术、理念或需求。创始团队或核心推动者是谁，之前做过什么，为什么是他们来做这件事。当时的行业是什么样子。有没有某件事直接促成了它。
- **诞生**：首次发布、成立或提出的确切时间，最初的形态和定位，和今天有什么不同。
- **演进**：按时间梳理关键节点。重大版本、融资、团队变动、战略转型、架构变化、用户规模的里程碑、重要的合作或收购、公关危机和争议。
- **决策逻辑**：每个关键节点上，尽量还原为什么这么选。为什么是 A 不是 B，当时受什么约束。哪些早期决定锁定了后来的方向，是什么机制让它越走越深（网络效应、生态绑定、技术栈的选择）。
- **阶段**：把整个历程自然地分成几段，每段有自己的特征和主要矛盾。

纵轴写成故事，不写成年表。「2023 年 1 月发布了 A，3 月发布了 B」是年表；它为什么在那个时间点突然爆发，之前铺垫了什么，转折在哪，这才是故事。

## 三、横轴：今天的竞争图谱

以今天为切面。先判断竞品的情况：

- **没有直接竞品**（全新品类或独占性很强）：不硬凑对比。改为分析它为什么没有对手，是品类太新、壁垒太高还是市场太小；最可能从哪个方向冒出竞争者；有没有间接的替代方案或上一代的做法可以参照。
- **一两个竞品**：逐个深入对比。
- **三个以上**：挑最有代表性的三到五个展开，篇幅按重要性分，其余的简要带过。

对比的维度按对象的类型调整，至少覆盖：

- **核心差异**：技术路线或底层逻辑，产品形态或商业模式，目标用户和适用场景，优势和明显的短板，定价和体量。
- **用户视角**：真实用户怎么评价每一家，被提到最多的优点和槽点是什么，用户实际的用法和官方的定位有没有偏差。每一家都要有，引用真实用户的原话并挂上原帖，不只转述官方宣传。
- **生态位**：研究对象在整个赛道里占什么位置，是填了一块空白还是在和谁正面竞争。现在的格局是百花齐放、两强相争还是一家独大。
- **走向**：从横向对比看，它的机会和风险各在哪里。

不把横轴写成参数对照表的文字版。要讲清每一家「活成了什么样」，用户选它的真实理由是什么。表格可以有，放在叙述旁边帮读者对照，不代替叙述。

## 四、交汇：两条线叠起来

这是全篇最值钱的一段。它要给出新的判断，不能是前面内容的缩写。要回答：

1. **历史怎样塑造了今天的位置**：纵轴上的哪些决定和事件，决定了它在横轴对比里的位置？
2. **把竞品也放到时间线上**：主要竞品各自的起源和演变路径有什么不同，这些不同怎样造成了今天各自的特点？
3. **优势从哪来**：今天的每个核心优势，能追到历史上的哪个节点或决定？
4. **劣势从哪来**：今天的每个核心劣势，能追到哪个决定？当初的好决定有没有变成今天的包袱？
5. **接下来会怎样**：给三个剧本，最可能的、最危险的、最乐观的。每个剧本写清它成立的前提，以及未来一年左右能看到哪些具体信号说明它正在发生，都要有前文的事实做支撑。研究对象不适合谈剧本时（比如已故的人物、已经定型的历史概念），改成对它留下的影响下判断。

写完检查一遍：这一段里的每个判断，是不是都同时用到了纵轴和横轴的材料？只用了一条线的，属于前面的章节。

## 怎么写

这是一篇让人能从头读到尾的深度研究，不是冷冰冰的咨询报告。它既要有研究报告的严谨，也要好读。

- **每个关键事实挂出处。** 日期、数字、引语、谁做了什么，后面跟一个编号，比如 [12]，对应文末「信息来源」里的同一条。读者要能顺着编号核对任何一句话。你自己的判断和推断不挂编号，明说是判断。
- **用具体的东西代替概括。** 不写「该公司在这一阶段实现了快速增长」，写「从 2024 年中的 1000 万美元 ARR 到 2025 年底的 10 亿美元」。产品和模型说具体的名字，不说「某个 AI 工具」。
- **叙事推着走。** 纵轴要有起承转合。背景知识在讲的过程中顺手带出来，不单开一段「下面科普一下」。
- **一层层剥开。** 先摆现象，再给表面的解释，然后追问一步，最后到核心的判断。让读者跟着推理走一遍，不直接把结论丢给他。
- **敢下判断，判断要有依据。** 先摆事实再给判断。判断用「我的判断是」「我觉得」这种承认主观的说法，不摆出下定论的姿态。推测明说是推测。
- **证据多不等于段落密。** 一段只讲一件事，三四百字还没完就拆开。横轴每家单独一个小节。出处靠编号挂在句尾，不把来源的名字和日期一串串写进句子里。
- **有节奏。** 句子有长有短，段落不必等长。偶尔让一句话单独成段，让它有分量。岔出去讲一个案例或一点背景之后，用一句话接回主线。
- **前后呼应。** 开头或纵轴里埋下的细节，在交汇或结尾处接回来，报告读起来才是一个整体。
- **可以往大处连，不硬连。** 交汇部分可以联系到更大的历史、文化或商业规律，前提是它确实从材料里长出来。没有就不写。

报告和公众号文章不同的地方：要有清晰的章节和小标题，一两万字没有导航读者会迷路；冒号、破折号正常使用；口语可以有，但密度要低，不满篇「这玩意」「太牛了」；结尾不加求关注、求转发的话。

写完后通读一遍，删掉这些：

- 套话：「首先……其次……最后」「综上所述」「值得注意的是」「不难发现」；
- 空洞的词：「赋能」「抓手」「打造闭环」；
- 教科书式的开头：「在当今 AI 快速发展的时代」「随着技术的不断进步」；
- 自问自答和假转折：「这意味着什么？」「说白了」「本质上」「换句话说」「不可否认」；
- 任何没有来源的具体事实。搜不到就写「该信息暂缺」。

改这些句子时，先找它原本想说的事实，用普通的话说出来，不换成另一种漂亮的套话。

## 不同研究对象的侧重

纵向追时间深度、横向追同期广度这一点不变，侧重点跟着对象走：

- **产品**：纵轴看版本迭代、技术路线的演变、用户增长、关键的产品决策；横轴看功能、性能、体验、定价。
- **公司**：纵轴看创始团队、融资、战略转向、组织变化、关键人事；横轴看商业模式、市场份额、营收、组织方式。
- **概念**（技术范式、商业模式、文化现象）：纵轴看谁提出的、基于什么理论或需求、怎么流行起来、经历过哪些争论和演变；横轴看它和相近概念的区别、各自适用的场景、不同阵营怎么论证。
- **人物**：纵轴看个人经历、职业轨迹、关键决定、公开言论的变化；横轴看和同领域其他人的对比，做事方式、成就、影响力、路线选择。

## 篇幅

默认交付一份完整的长报告。下面是参考范围，不是要凑的字数：

| 部分 | 参考字数 | 说明 |
|---|---|---|
| 纵向分析 | 6,000–15,000 | 主体。历史长、节点多的靠近上限，新生事物靠近下限 |
| 横向分析 | 3,000–10,000 | 没有直接竞品时 3,000 左右；竞品多时按重要性分配 |
| 横纵交汇 | 1,500–3,000 | 给出新判断 |
| 全文 | 10,000–30,000 | |

篇幅由节点的数量和证据的密度撑起来。关键节点值得展开就展开，不为了压缩跳过重要的细节；证据少就写短，并说明缺口在哪，不靠重复和换个说法填字数。用户指定了篇幅、时限或重点时照他的来。用户想快速读完时，在正文前加一段结论摘要、一条关键时间线和一张竞品对比表，叙述部分保留。

## 成稿与交付

Markdown 稿按这个结构写：

```
# 报告标题
> 研究时间：... | 所属领域：... | 研究对象类型：...

## 一、一句话定义
## 二、纵向分析：从诞生到当下
## 三、横向分析：竞争图谱
## 四、横纵交汇洞察
## 五、信息来源
```

- 第一行的 `# 标题` 会被脚本取作封面标题，正文里不再重复。紧跟标题的 `>` 一行是元信息，会放到封面上。
- 主章节用 `##`，子章节用 `###` 和 `####`。表格、引用、加粗都用标准 Markdown 语法。
- 「信息来源」用有序列表（`1.` `2.`）按正文里的编号逐条列出，不写成 `[1]: 网址` 的形式（那是 Markdown 的链接定义，转换时会被吃掉），每条写标题、URL、发布日期和来源性质（一手、二手、当事方自述），并注明访问日期。末尾用一两句话说明横纵分析法的来历。

交付格式：

- **默认**：PDF，同时保留 Markdown 源稿。文件名 `[研究对象]_横纵分析报告.pdf` 和同名的 `.md`，存到用户的工作目录或他指定的位置。
- **HTML**：用同一个脚本，输出文件的扩展名写 `.html`，不需要 WeasyPrint。
- **只要 Markdown**：直接交付，不运行转换。
- **Obsidian**：把 Markdown 存到用户指定的 vault 路径，存完读回来核对一遍。

转换步骤：

1. 找到这个 Skill 实际所在的绝对目录，记为 `HV_SKILL_DIR`。路径里有空格也要能用，命令里加引号。
2. 准备 Python。优先用已有的环境；需要装依赖时，在用户的缓存目录里建或复用一个 venv（macOS 和 Linux 用 `~/.cache/khazix-skills/hv-analysis`，Windows 用 `LocalApplicationData` 下的 `khazix-skills/hv-analysis`），把这个环境里 Python 的绝对路径记为 `HV_PYTHON`。项目目录里只放稿件和报告。不使用 `--break-system-packages`。
3. 装依赖。HTML 只需要 `markdown`；PDF 另外需要 `weasyprint` 和它要求的系统库 Pango，安装说明见 https://doc.courtbouillon.org/weasyprint/stable/first_steps.html#installation 。
4. 运行转换。用户给了署名才加 `--author`，没给就去掉，封面上不写作者：
   ```bash
   "$HV_PYTHON" -m pip install markdown
   "$HV_PYTHON" "$HV_SKILL_DIR/scripts/md_to_pdf.py" input.md output.pdf --title "研究对象名称" --author "报告作者"
   ```
   PowerShell 里写成 `& $HV_PYTHON "$HV_SKILL_DIR/scripts/md_to_pdf.py" ...`。
5. 输出 PDF 时会同时生成一份 HTML，输出 HTML 时只生成 HTML。封面、页眉页脚、配色、中文字体和表格样式脚本都已经内置，不需要手动调。打开实际的产物，核对标题、中文、表格和分页是否正常。

PDF 依赖装不上时，告诉用户卡在哪，先交 HTML 或 Markdown。

## 交付前
